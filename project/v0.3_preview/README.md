# SDITADC v0.3_preview

更新日期：**2026-10-14**。本文面向运行和使用；AI工具细则见 [AI能力说明](ai/AI能力说明.md)，接手仓库先读 [根README](../../README.md)。

在HTML双窗口、Three.js 3D、Canvas 2D和多机器人调度基础上，新增DeepSeek业务助手。默认三机，保留多地图和地图容量内的机器人数量配置。

## 启动

双击 [launch.bat](launch.bat)。本机新版独立 `.venv` 已安装依赖；其他机器首次使用：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\launch.bat
```

可选入口：

```powershell
.\.venv\Scripts\python.exe main.py --paused --debug-window
.\.venv\Scripts\python.exe main.py --browser --paused
.\.venv\Scripts\python.exe main.py --serve --paused --no-save
.\.venv\Scripts\python.exe main.py --map warehouse_64x48 --robots 8 --paused
```

没有配置API时，仿真、地图和手动任务仍可正常使用。

## 配置DeepSeek

1. 点击主窗口右上角「AI 设置」。默认地址 `https://api.deepseek.com`，支持自定义兼容地址及 `/v1` 前缀；外部使用HTTPS，HTTP仅供本机测试。
2. 填写API Key。默认仅本次运行有效；「记住密钥」存入Windows凭据管理器，提供删除入口。
3. 点击「获取模型」，从模型ID输入框选择，或手动填写。显示可读名称，实际使用ID，不自动替用户选择模型。
4. 思考程度为「关 / low / high / max」，默认high。不支持的档位不能使用。
5. 「测试连接」验证真实只读工具往返，可能产生少量用量；模型列表成功不等于工具验证通过。
6. 保存后切换右侧「AI 助手」。地址或模型变更后隔离旧上下文；地址变更需明确重新填写密钥。

非敏感配置写本目录 `local_settings.json`，默认不提交。密钥不写配置、浏览器存储、聊天、日志或场景；凭据保存失败明确提示仅本次有效。

Key已配置时，输入框显示固定圆点；获取模型、保存或重新打开设置后仍会显示。圆点是配置状态提示，不代表真实Key长度或认证通过，也不会被作为新Key提交。删除密钥后圆点消失；更换API地址时旧地址的圆点不显示，需明确重新输入Key。

后端代码更新后需重启程序；未选择“记住密钥”时，重启需重新填写Key。仅刷新网页不会重新加载Python后端工具库。

## 业务能力

- 查询任务、机器人状态和当前有效作业点。
- 创建取送任务：默认2级，明确紧急为5级。
- 提升一级或指定更高等级；不能降级，结束任务不能升级。
- 取消待分配、预约、前往取货任务；装货开始后不可取消。
- 查询完成数量、距离、任务周转和下单至装货耗时。单位为调度时间步，不是秒；下单至装货含路程，不是纯排队等待。
- 装货前人工指定机器人、解除指定恢复自动、设置软偏好，以及复制已有任务。完整工具清单与示例见 [AI能力说明](ai/AI能力说明.md)。

```text
有哪些取货点和配送点？
从取货点4送到D2，设为紧急，并告诉我谁接手。
把T003提升一级。
取消这个任务。
将T007分配给R3。
解除T007的指定，恢复自动分配。
T007优先交给R3，忙不过来用其他机器人。
照T007再创建两次搬运任务。
```

「这个任务」使用发送时显示的关联对象；不明确时澄清。途中更换选中任务不改变已发送对象。AI只响应用户，不自主改任务；明确指令执行，讨论或假设不执行。没有暂停、速度、地图、种子、数量、记录或自动生成等调试工具。

人工指定允许锁定当前执行者，或装货前改派到没有其他任务的机器人；不抢占忙碌机器人的其他任务，装货开始后不能调整。指定关系保留，但紧急任务可以暂时抢占未装货普通任务，后者继续等待指定机器人。指定不提高等级，不能绕过待分配任务的硬优先级。

软偏好先服从各等级分配数量，再优先满足可立即接手机器人的偏好，最后最小化预计完成时间；忙碌时允许其他机器人接手。解除指定或偏好后重新自动分配。查询、任务列表和结果卡分别显示分配方式、请求机器人和实际执行者。

复制一次最多20份，默认继承原取送地点与等级，也可明确覆盖新等级；原任务不变，新任务不继承状态、机器人、指定或偏好。复制完成或取消的任务也只创建新任务。分配设置和复制来源写入输入事件，兼容旧记录，回放不调用模型。

调度沿用紧急接手与剩余空闲机器人两阶段匹配；每阶段在可选槽位及人工约束下优化优先级、偏好和预计完成时间，不宣称整个在线过程全局最优。

### 四种常用操作

| 中文指令示例 | 执行行为 |
| --- | --- |
| “将T007分配给R3。” | 装货前锁定当前执行者或改派到无其他任务的R3；指定持续保留，不抢走R3的其他订单 |
| “解除T007的指定，恢复自动分配。” | 清除人工指定或软偏好并重新调度；任务仍然存在，执行者可能变化 |
| “T007优先交给R3，忙不过来用其他机器人。” | 设置软偏好；在每阶段硬优先级之后优先满足可立即接手的偏好，不保证实际执行者为R3 |
| “照T007再创建两次搬运任务。” | 新建两条独立任务，默认继承原地点与等级；原任务不变，不继承指定或偏好 |

任务编号仅为示例，实际按任务列表或查询结果使用。每台机器人同时最多一个未结束人工指定任务，不支持人工安排连续订单队列。已使用同一分配方式与机器人时返回“无需改变”。装货后拒绝调整分配；不存在的ID、忙碌目标或绕过硬优先级的指定也会明确拒绝，AI不应自行取消其他订单来绕过限制。

## 按货架名称下单

可以输入「将四号货架的货物送到二号配送点，设为紧急」。数字/中文数字、送到/运往等表达由上游LLM理解；程序提供地图的正式货架—取货点关系和地点名称，不在本地编写中文意图匹配器。

`get_locations`现可查询 `kind=shelf` 或 `all`，返回货架ID、名称、别名和对应pickup_id，以及配送点名称/别名。模型将查询结果转换为现有 `create_tasks` 参数；货架编号与取货点编号可以不同。结果卡显示真实取送名称。

标准仓库登记20组货架，中型仓库登记64组。MovingAI取货点邻接多组货架，未自动登记单一货架归属；使用取货点ID下单，或先在地图中明确配置。旧地图/旧快照缺少登记时仍可使用取货点，不自动猜测货架。

地点缺失、未登记或多个候选时，提示词要求先追问；后续回复可补齐同一个未执行请求。当前没有货物品种或库存模型，一条任务代表一次搬运，「全部库存」需要明确数量。自定义「包装区」「出货口」等名称要先在地图 `locations` 中配置，不能由模型任意对应。完整格式见 [地图说明](maps/README.md)。

脚本化模型测试验证元数据查询、工具调用和真实业务执行，不代表真实DeepSeek已理解所有中文表达；实际语言效果仍需在应用中配置模型验证。

## 真实结果和停止

以本地业务结果卡为准，模型文字不是成功证明。创建、分配、预约接手、装货、配送和完成不同，静态阶段不证明实际位移。

暂停时可下单、分配、规划，保持暂停；模型不接收暂停等调试字段。紧急不会打断装卸或丢弃载货，必要时预约交付后接手。

创建、提升、取消或复制的每次批量工具调用最多20项：整批预检，逐项执行；中途失败保留已成功项、停止剩余项，不自动回滚。指定、解除和偏好每次工具调用处理一个任务。操作标识防止同次操作重复下单；跨新消息重发不保证去重，超时后先核实已生效结果。

一次处理一条消息，期间可编辑草稿。Enter发送、Shift+Enter换行。「停止回复」阻止后续生成和未开始调用，已开始的原子动作可能完成，已生效操作不会撤销。

聊天仅本次运行，可清空。重置、加载、更换地图或数量显示「工作场景已更新」，旧消息仅供查看，旧关联和待执行请求失效。旧结果卡不能跳到新场景同名任务。

## 上下文与结构

预算达到阈值时自动摘要早期对话，保留最近完整轮次；摘要失败则裁剪完整旧轮次，原可见消息保留。摘要不是实时状态，工具重新查询。不实现向量库或长期Agent记忆。

high/max及摘要增加等待与用量。单轮默认300秒，可调整30～900秒；调用次数有上限。显示事件有4096条缓存，续取事件不重发业务操作。

`ai/` 分离配置、凭据、DeepSeek流式、提示词、十类工具、actor执行、会话和工作线程。`frontend/chat.js`、`settings.js`提供界面。Controller仍为唯一状态写入者；模型网络不阻塞仿真线程。写工具经过领域命令，在人工指定约束及软偏好下自动调度和协调路线。

算法、地图和数量限制见 [基准版本说明](../v0.2.1_preview/README.md) 和 [地图说明](maps/README.md)。沿用精确匹配、CBS和预约寻路备用方案，不等于整个在线过程全局最优。
