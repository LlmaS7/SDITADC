当你接手、解释或继续修改本项目时，请先核对当前文件，再阅读本 README 和当前版本说明。以下记录更新于 **2026-10-13**。

1. **当前开发入口是 `project/v0.2.1_preview/`。** 当前版本采用 HTML、Three.js 3D、Canvas 2D，并拆分为使用者主窗口与独立调试窗口，源码、场景、测试、环境和输出位于版本目录。`v0.1_preview/` 保留为原 Pygame 2D 版本。新功能和修复应放在对应模块，保持模块划分。
2. **`learning/` 是学习资料和早期实验。** 其中的 handoff 和教学记录包含历史状态，例如“project 为空”“完整系统尚未实现”。这些描述已经不能代表当前预览版；当前进度以本 README、版本说明和实际代码为准。
3. **坚持已确认的范围。** 默认三台机器人，数量可在地图上限内配置；采用静态障碍和离散四邻域运动。主窗口显示 3D、2D 和任务列表，调试操作与内部数据放在独立窗口，两者共用一份仿真状态；3D 是简化展示，不是新的物理引擎。默认只提供普通仓库场景，紧急任务交互功能保留，不添加未请求的特殊演示预设。
4. **区分匹配最优与整体运行最优。** 当前任务分配是本轮、给定代价模型下的精确匹配，不是整个在线任务过程的全局最优。不要把估计代价、CBS 的局部优化范围或有限时域搜索夸大为全局保证。
5. **保护任务和货物状态。** 已载货机器人必须先交付；装卸动作是原子动作。取消任务只从界面列表移除，内部取消记录保留供报告及回放使用，不能直接删除记录而破坏状态机。
6. **保护学习数据和运行记录。** 不覆盖、移动或重排 `learning/maps/`。依赖安装在版本独立环境，不安装到全局 Python。`outputs/` 包含用户可能需要的场景和记录，清理前辨明用途。
7. **围绕用户已授权的工作修改。** 先确认当前实现和问题触发条件，再做针对性改动；不要擅自扩展到真实机器人、ROS、SLAM、连续控制或大型界面重构。用户的新要求优先于历史文档。
8. **如实报告验证范围。** 已运行检查、用户反馈、理论推断和未来计划分别记录。学习理解程度不能仅凭用户说“能理解”就记为已验证掌握。
9. **同步维护文档。** 修改入口、目录、状态规则、优化目标或参数后，更新本 README 与版本说明。测试按修改影响选择；文档或简单显示调整不需要无目的地重复整套长时间运行。

# SDITADC：智能仓库多机器人协作仿真

项目面向大学生智能技术应用设计类竞赛，当前已完成可配置机器人数量的仓库 HTML 双窗口预览版：主窗口展示 3D、2D 和任务列表，调试窗口集中提供测试操作与内部信息。

**任务进入 → 优先级任务分配 → 多机器人路径协调 → 取货与送货 → 持续执行 → 可视化与记录。**

建模方向接近 MAPD（多机器人取送任务）与 Lifelong MAPF（持续接收目标的多机器人寻路）。当前阶段是软件仿真，算法与界面分离；真实机器人和连续运动控制不是本版本的前置条件。

## 快速启动

Windows 下双击：

```text
project/v0.2.1_preview/launch.bat
```

默认打开最大化的主窗口，不保留额外命令行窗口；点击右上角“调试窗口”可打开独立调试窗口。关闭调试窗口不影响主窗口，再次打开保持状态；关闭主窗口一并关闭调试窗口、停止后台并保存记录。启动失败时提示 `project/v0.2.1_preview/outputs/startup_error.log` 的位置。

默认场景为 **32×24 标准仓库、3台机器人、9个普通任务**，自动生成任务关闭。普通启动使用地图默认配置，不自动恢复上次选择；加载记录可以恢复记录中的地图、机器人数量和输入事件。

或从 `SDITADC/` 根目录执行：

```powershell
& .\project\v0.2.1_preview\.venv\Scripts\python.exe .\project\v0.2.1_preview\main.py
```

当前机器已验证的环境是 **Python 3.14.5、pywebview 6.2.1、pythonnet 3.2.1 和 WebView2**。Three.js 0.186.1 已保存在版本内，正常运行不需要 Node、npm、Vite 或 CDN。旧 v0.1 的 pygame-ce 环境保留在旧版本内；新版本不依赖 Pygame。

Windows 独立窗口使用 WebView2 和 .NET 运行时，3D 使用 WebGL 2。不要直接双击 `frontend/index.html` 代替启动入口：页面必须连接当前仿真状态与命令服务。前端渲染库已在本地，完成环境安装后无需联网加载 3D 资源。

换电脑或环境缺失时，在版本目录重建环境：

```powershell
Set-Location .\project\v0.2.1_preview
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

虚拟环境依赖本机 Python 路径，不应直接复制到另一台电脑后当成可移植安装包。

### 可选运行方式

以下命令在 `project/v0.2.1_preview/` 目录中执行：

```powershell
# 独立窗口，初始暂停
.\.venv\Scripts\python.exe main.py --paused

# 启动时同时打开两个独立窗口
.\.venv\Scripts\python.exe main.py --debug-window

# 使用64×48中型仓库和8台机器人，初始暂停
.\.venv\Scripts\python.exe main.py --map warehouse_64x48 --robots 8 --paused --debug-window

# 普通浏览器主页面提供调试页面入口
.\.venv\Scripts\python.exe main.py --browser

# 只启动本机服务，不自动打开窗口
.\.venv\Scripts\python.exe main.py --serve --paused

# 加载指定场景输入记录
.\.venv\Scripts\python.exe main.py --load outputs/last_scenario.json --paused
```

服务仅监听 `127.0.0.1`，默认自动选择可用端口；可通过 `--port` 指定。`--browser`、`--serve` 模式使用控制台停止服务。验证时可加 `--no-save`，避免退出时覆盖已保存记录。

## 窗口分工

| 窗口 | 内容 |
|---|---|
| 主窗口 | 3D、2D、机器人状态、任务列表、暂停/速度、任务等级与取消；顶部以完成、执行中、待处理数量呈现运行概况 |
| 调试窗口 | 场景设置（地图、机器人数量、种子）、随机/自定义任务、自动生成、单步、重试、保存/加载；时刻、快照编号、当前路线算法和规划指标 |

主窗口不显示种子、仿真步数、CBS节点、规划耗时和分配代价。两个窗口共用同一控制器，打开调试窗口不另起仿真。单步等调试快捷键只在调试窗口生效。

## 地图、机器人数量与视图操作

当前地图文件均位于 `project/v0.2.1_preview/maps/`，使用独立的 **sditadc-map v1 JSON**。地图规格版本与程序版本分别编号。

| 地图 | 文件名 | 尺寸 | 默认数量 | 数量上限 | 布局 |
|---|---|---|---|---|---|
| 标准仓库 | `warehouse.json` | 32×24 | 3台 | 6台 | 20组货架，按种子叠加最多20个静态随机障碍 |
| 中型仓库 | `warehouse_64x48.json` | 64×48 | 3台 | 8台 | 64组5×3货架，横纵间隙至少2格，中央横纵主通道各4格 |
| MovingAI仓库 | `movingai_warehouse.json` | 161×63 | 3台 | 6台 | 从本地基准地图转换，另配取送点和停车位；部分通道仅1格宽 |

修改场景：打开主窗口右上角的“调试窗口”，在“场景设置”中选择地图、机器人数量和种子，点击 **“应用并重置”**。任务、机器人状态和仿真时刻一起重置，随后保持暂停。数量选择不会立即改变仿真；切换到容量更小的地图时，待应用的数量会显示为新上限。

每张地图通过 `robots.default_count` 定义默认数量、`robots.max_count` 定义上限。`points.starts` 是按相邻顺序排列的起点池，前N个位置对应R1～RN；上限不能超过有效起点池或停车位数量。当前程序最多允许12台，现有地图采用更低上限。提高上限时需要补足起点和停车位，并验证布局与规划性能，不能只改数字。

地图的 `grid.rows` 以每个字符表示一格：`.` 为地面，`#` 为墙，`R` 为货架，`O` 为固定杂物。取货点、配送点、停车位和起点池单独存储。支持宽高各3～256格，所有地面须四方向连通；地图几何校验不保证任意任务负载都能在规划预算内完成。

新增地图后，在调试窗口点击“刷新列表”即可发现文件。原始MovingAI `.map` 需要先转换并配置作业点；`.scen` 是静态起终点测试数据，不是仓库取送任务。完整示例、校验和转换命令见 [地图规格](project/v0.2.1_preview/maps/README.md)。

种子控制随机障碍和随机任务：同一地图、数量和种子可以复现初始场景；没有随机障碍的地图更换种子只影响随机任务。

| 视图 | 操作 |
|---|---|
| 3D预览 | 拖动旋转、滚轮缩放，“恢复视角”重新取景 |
| 2D预览 | 鼠标位置锚定滚轮缩放（适配全图的1倍至12倍）、左键拖动平移，“恢复视图”显示全图 |

二维视图在窗口尺寸变化时保留缩放和中心位置，重置场景时恢复全图。放大只绘制可见网格，缓存始终保持视口尺寸；两个视图继续使用同一份机器人位置，缩放不改变任务和路径规划。

## 当前已实现

| 部分 | 当前行为 |
|---|---|
| 地图 | 统一 sditadc-map v1 JSON；默认 32×24 仓库，可选 64×48 中型仓库（货架间隙至少两格）和转换的 161×63 MovingAI 仓库；调试窗口选择地图、刷新列表、应用并重置；布局、作业点和相邻起点都在地图文件中，校验连通性 |
| 机器人 | 默认3台，调试窗口可设置1～地图上限；标准仓库6台、中型仓库8台、MovingAI仓库6台；从起点池前N个相邻坐标出发，每台一次搬运一件货物 |
| 任务 | 前往取货、装货、送货、卸货；装卸各 2 步，多个任务可共享作业点并错峰占用 |
| 任务输入 | 默认 9 个普通任务；支持手动指定、随机新增和自动生成；自动生成默认关闭，开启后每 45 步新增一个普通任务 |
| 分配 | 按硬优先级分层，再精确最小化本轮预计完成时间总和；普通任务派出后通常保持归属 |
| 紧急任务 | 5 级为紧急；立即重新调度，选择预计最早完成的合适机器人；可抢占尚未开始装货的普通任务，原任务返回队列 |
| 载货与原子动作 | 不强行中断装卸或丢弃货物；必要时预约机器人完成当前搬运后接手紧急任务；同级紧急任务不互相抢占 |
| 多机寻路 | 时空A*与CBS；预算耗尽后尝试完整预约寻路（不保证联合路径最优）；检查同格和对向换边冲突，路线覆盖作业及独立停车终点 |
| 界面 | 主窗口显示3D、2D、任务和日常操作；调试窗口显示任务注入、单步、记录管理、种子、时刻及性能信息；共用状态 |
| 任务操作 | 升级紧急、提升等级、取消未开始装货任务；取消后从所有界面列表移除并更新显示总数，内部记录仍保留 |
| 位置高亮 | 选中任务后同时高亮3D和2D取送位置；二维“取”字位于数字标记上方；支持清除高亮 |
| 二维视图 | 鼠标位置锚定滚轮缩放（1～12倍）、左键拖动平移、“恢复视图”显示全图；切换地图后恢复全图，窗口调整保留缩放与中心位置 |
| 执行控制 | 暂停、继续、单步、速度调整、重置和重试规划；暂停时可以修改任务，位置及仿真时间保持不动 |
| 记录 | 保存机器人数量、种子、完整地图快照和输入事件，回放不依赖原地图文件；旧记录没有数量时按3台读取，加载后暂停 |
| 规划异常 | 有计算预算和搜索时域；扩大时域重试后尝试预约寻路，仍失败或持续无进展时暂停；只执行经完整冲突检查的路线集合 |

### “最优”的范围

任务匹配的代价为：

```text
剩余必要动作时间
+ 到取货点的网格最短路
+ 装货时间
+ 取货点到配送点的网格最短路
+ 卸货时间
```

距离依据实际障碍地图上的 BFS。匹配使用机器人占用位掩码动态规划，针对本轮候选机器人、候选任务和给定代价精确求解。

**代价不预测未来插单及后续路径冲突带来的等待。** 分配最优不等于实际完成时间全局最优，也不等于整个持续运行过程的全局最优。

CBS 的优化目标依次是紧急任务交付时间和、全部交付时间和、停车到达时间和。其范围受固定任务归属、固定作业顺序和搜索时域限制；达到计算预算或节点上限时报告超时，不作无解或最优证明。

机器人数量增加后，CBS可能耗尽预算，随后尝试按顺序预留顶点、反向边及长期停车占用的预约寻路。它只提供经过冲突验证的完整可行路线，不保证联合路径最优或一定能找到方案。任务匹配仍精确；停车位使用匈牙利算法精确最小化总距离，避免枚举排列。地图容量、默认数量及相邻起点池见 [地图规格](project/v0.2.1_preview/maps/README.md)。

### 关键执行规则

- 坐标统一为 `(x, y)`，x 向右、y 向下。算法使用网格坐标，界面自行转换像素。
- 机器人最终停车后仍保留占用，不会从地图消失。作业点不作为长期停车位。
- 紧急任务的“立即调度”表示在安全边界立即重新安排；不是瞬移、碰撞穿越或中断载货交付。
- 装货开始后任务不能取消。被紧急抢占的普通任务保留编号、等级与原始创建时间。
- 普通任务长时间等待会告警，但不会自动升为紧急任务；目前不提供严格优先级下的无饥饿保证。
- 网页读取同一JSON快照，controller的单线程负责状态、命令和规划；3D与2D共用同一插值位置。刷新或打开第二个页面不另起仿真。
- 1～3机每次CBS预算2秒，4机以上每次CBS预算0.35秒；扩大时域重试一次后尝试2秒预算的预约寻路。最低时域260步、CBS节点上限6,000，长地图按最短路及作业时间增加时域。参数见 `config.py`。

### 展示与仿真的模块边界

```text
任务栏和控制按钮
        ↓ 提交命令
controller.py：唯一状态拥有者和仿真时钟
        ↓ 调度、规划和执行
scheduler.py / planning/ / simulation.py
        ↓ 发布同一份JSON快照
frontend/app.js：共用位置插值
        ├── scene3d.js：3D展示
        ├── map2d.js：2D展示
        └── 任务列表、机器人状态和指标
```

3D仅把二维网格映射到地面；相机、货架高度和动画不改变算法的障碍或碰撞规则。不要让网页计时器独立推进任务，也不要为了3D另建一套机器人状态。

## 保存、加载与兼容性

保存或正常退出时写入当前版本的 `outputs/last_scenario.json` 和 `outputs/last_run.json`。前者保存地图快照、数量、种子和输入事件，后者记录任务、机器人、指标及逐步状态。地图快照包含已经生成的随机障碍，原地图文件修改或删除不影响新记录的加载。

加载是从起始场景重新执行输入事件，不是从退出时刻恢复中途状态。限时CBS与备用预约寻路可能随运行环境选择不同路线，因此不承诺跨机器逐步路径相同。读取旧0.1、0.2及0.2.1记录时，缺少数量字段按3台处理，缺少地图快照则依赖当前标准仓库和记录种子。

场景设置在本次运行中生效；普通启动使用地图默认值，要复用记录中的选择可使用“加载记录”或 `--load`。验证时加 `--no-save`，避免覆盖用户已有场景和报告。

## 常见界面说明

- **“取”“送”一直显示：** 它们表示当前选中任务的位置。完成后也可查看；点击另一个任务会切换，新HTML版还提供“清除高亮”。它们不代表机器人仍在装卸货。
- **取消后编号出现空缺：** 编号保留原有身份，不重新编号；取消任务从列表隐藏，记录保留在报告中。
- **自动生成关闭仍有任务：** 启动时自带 9 个普通任务；开关只控制后续自动新增。
- **全部任务完成后机器人仍移动：** 机器人可能正在前往停车位，二维预览旁的机器人状态卡会标明。
- **修改数量后任务重新开始：** 数量修改通过“应用并重置”生效；当前版本不在任务执行中热增删机器人。
- **更换种子后地图形状未变：** 种子不会改变固定货架布局；没有随机障碍的地图只改变随机任务。
- **二维地图放大后看不到全图：** 拖动平移查看其他区域，或点击二维区域右上角“恢复视图”。
- **3D区域无法显示：** 页面会提示WebGL问题，2D和任务操作仍可使用；应检查WebView2、显卡加速及实际渲染情况，不通过修改寻路规则解决显示问题。
- **窗口弹出较慢：** 用户曾反馈旧Pygame版启动等待；旧SDL的局部测量不能代表新HTML版冷启动。新版本要加载WebView2和.NET，独立窗口页面就绪后才开始默认仿真。具体用户端启动时间尚未实测，不能把等待直接归因于CBS；测试目录不会随正常启动执行。

## 当前边界与后续工作

当前未实现真实库存、货物重量、电池、多件装载、运行中动态障碍、连续速度与加速度控制、真实车体尺寸、ROS/SLAM、真实机器人接口，以及中途状态存档恢复。当前支持统一文件地图及 MovingAI 转换，格式与新增方法见 [地图规格](project/v0.2.1_preview/maps/README.md)。机器人数量在每地图上限内配置，按相邻起点池生成，采用四方向移动；地图校验不保证任意狭窄布局都能在规划预算内完成。
