7. **最优范围要准确。** 现有分配在人工指定约束下，按硬优先级、可立即接手的软偏好和本轮预计完成时间精确匹配。CBS范围受归属、顺序、时域和预算限制；预约备用寻路只保证已验证的可行路线，不宣称在线全局最优或任意布局无死锁。

11. **人工分配关系属于领域状态。** `Task.assignment_mode`为auto/forced/preferred，`assignment_robot_id`保存请求机器人，实际接手仍看`robot_id`；`copied_from`保存复制来源。维护时同时核对调度、业务回执、界面和assignment/copy事件回放，不只改提示词。每台机器人最多一个未结束人工指定任务；装货后禁止调整分配。

# SDITADC：仓库多机器人协作与业务助手

面向智能技术应用设计竞赛的软件仿真：任务进入、硬优先级匹配、多机器人路径协调、取送执行、可视化和记录。建模接近MAPD及Lifelong MAPF，当前不要求真实机器人和连续物理控制。

## 启动和使用

双击 `project/v0.3_preview/launch.bat`。本机已有新版独立环境；其他机器按新版README重建 `.venv` 并安装requirements，不能把虚拟环境当便携安装包。

主窗口同时显示3D、2D、机器人状态和右侧任务/AI选项卡；调试窗口提供任务注入、自动生成、单步、地图/数量/种子、保存加载及内部指标。两个窗口共享同一个Controller，不另起仿真。

AI设置由主窗口入口打开：填API地址和Key、获取或手填模型ID、选择思考程度、测试并保存。默认地址为 `https://api.deepseek.com`，允许自定义兼容地址；思考程度为关/low/high/max，默认high。未配置API也能正常运行和手动操作。

已配置Key以固定圆点显示，获取模型和重新打开设置后仍保留；圆点仅表示同地址已有密钥，不是实际Key或认证成功证明。Key默认只在本次运行，选择“记住密钥”才存Windows凭据；删除后圆点消失，更换地址须明确重新输入。Python后端工具更新需重启，未记住密钥时重启需重新填写。

```powershell
Set-Location .\project\v0.3_preview
.\.venv\Scripts\python.exe main.py --paused --debug-window
.\.venv\Scripts\python.exe main.py --browser --paused
.\.venv\Scripts\python.exe main.py --map warehouse_64x48 --robots 8 --paused
.\.venv\Scripts\python.exe main.py --headless --ticks 350 --no-save
```

本机服务仅监听127.0.0.1，默认自动选择端口。普通启动默认三台，场景变化通过既有调试入口应用；机器人数量不在执行中热增删。

## AI业务边界

十类工具为状态查询、作业点查询、创建任务、提升优先级、取消任务、业务指标、指定执行、解除指定、软偏好、复制任务。新任务默认2级，紧急5级；复制默认继承源任务地点与等级，可明确覆盖新等级。每次批量工具调用最多20项。完整说明见 [AI能力说明](project/v0.3_preview/ai/AI能力说明.md)。

指定与偏好只能在装货前调整；允许锁定当前执行者或改派到无其他任务的机器人，不抢占忙碌机器人的其他任务。指定关系在重规划及紧急抢占后保留，普通任务暂时被抢占后仍等待指定机器人；不能绕过硬优先级。软偏好可以回退到其他机器人，解除后恢复自动分配。复制产生独立新编号，不继承执行状态或指定/偏好。分配模式、请求机器人和实际执行者在查询、列表及回执中区分；分配设置与复制来源支持输入事件回放。

四个新工具分别为 `assign_task`、`release_task_assignment`、`set_task_preference`、`copy_task`。例如「将T007分配给R3」「解除T007的指定」「T007优先交给R3，忙不过来用其他机器人」「照T007再创建两次」。前三个每次调用处理一个任务；复制每次1～20份，默认1份。新消息的重复下单不保证去重，网络异常后先查询真实状态。

支持「将四号货架的货物送到二号配送点」式下单：语言表达由LLM理解，`get_locations`提供当前货架名称/别名、正式取货点关系和配送点名称。标准仓库登记20组、中型仓库64组；MovingAI和没有登记的旧地图不猜货架归属。货架编号可以与取货点编号不同，缺失或歧义地点先追问。自定义业务名称在地图 `locations` 中配置，随场景快照保留；当前没有真实库存模型。

明确指令执行，咨询或对象含糊时澄清。关联任务在发送时固定。只响应用户消息，不主动监控下单；算法继续承担选择机器人、紧急抢占/预约和路径规划。

结果卡由本地真实业务回执生成。整批预检后逐项执行，失败保留已成功项，不自动回滚；actor台账和操作标识防止同次请求重复创建。停止仅影响后续生成或尚未开始的调用，已生效操作不撤销。

暂停期间可下单、分配和规划，仍保持暂停；模型不接收暂停、时刻、种子、完整路线和内部规划信息。阶段不代表机器人实际位移，不能虚报已出发。

聊天仅本次运行。长对话达到预算自动摘要，失败裁剪完整旧轮次，原界面消息保留。场景或接入地址/模型更改隔离旧上下文，旧ID不会操作新场景同名任务。

## 调度、地图和记录

现有任务分配在人工指定约束下按硬优先级分层，再满足可立即接手机器人的软偏好，最后精确最小化本轮估计完成时间和，代价不预测未来插单与冲突等待。CBS覆盖作业和独立停车终点，耗尽预算后尝试预约寻路；只执行完整冲突验证过的路线。装货开始后取消或改派拒绝，普通未取货任务可被紧急抢占，忙碌机器人可能由紧急调度预约未来接手。

地图使用sditadc-map v1 JSON，当前标准仓库32×24、中型仓库64×48、MovingAI仓库161×63。默认三台，三张地图上限分别6/8/6，程序最多12台；提高上限需有效相邻起点和独立停车位，并验证布局性能。详情及转换命令见地图README。

3D拖动旋转/滚轮缩放，2D支持鼠标锚点缩放、拖动平移和恢复全图；两者使用同一位置插值，不改变网格寻路。

新版记录写本版outputs；兼容0.1、0.2、0.2.1和0.3场景。加载是初始输入事件回放，不恢复退出时刻或AI会话；回放直接复用领域事件，不再请求模型。旧版outputs不复制或覆盖。
