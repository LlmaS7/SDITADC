2.2：三个机器人怎样协商通道顺序

本课把上一课的优先规划扩成三台机器人，并让程序在固定顺序失败后尝试其他顺序。

表格展示一种安全时序：B 先通过主通道，A 和 C 在侧边等待，等 B 经过各自目标格后再进入。代码的 A* 可能因平局处理选择另一条同样安全的等待路线；应关注占用约束和先后关系。

为什么“换顺序”有用？

  1. 试 A → B → C：A 先到主通道目标并停留，B 无法通过，因此本轮失败。
  2. 每个顺序都是独立尝试；失败后必须清空预约表。
  3. 试 B → A → C：先让 B 通过；再规划 A、C，它们可以在侧边等待并在安全时间进入。
  4. 对最终方案再检查顶点冲突和对向换边冲突。
规划失败的含义：当前顺序或当前搜索时间范围内没有找到解；它本身不能证明所有协作方案都无解。

在 SDITADC/learning 目录中运行：

python teach/examples/three_robot_priority_search.py
  • plan_one：对一台机器人做带时间的 A*，遵守已预约的格子与边，并允许 WAIT。
  • plan_order：按给定顺序逐台规划。任何一台失败就停止本轮并报告它。
  • permutations：生成小规模机器人的不同顺序；每轮创建全新的预约表。
  • 终端输出尝试顺序、失败机器人、路线、等待次数和若干逐时刻地图。

目标格按“到达后停留”处理，因此 A* 只有在确认该格剩余规划时间内不会被其他机器人占用时，才把它当作最终目标。

为什么不该直接枚举很多机器人的顺序？

三台机器人有 6 种全排列；十台就有 3,628,800 种。这个程序把所有顺序按需尝试，只适合作为三台机器人规模的教学实例。固定优先级本身也不保证找到解或最短总路径。AAAI 关于优先级搜索的研究讨论了这类方法的局限。

后续如果要支持更多机器人和持续到达的仓库任务，可学习滚动时域规划：规划有限窗口、执行几步后再规划；也可了解每个时间步动态调整优先级的 PIBT，或反复修复冲突路径子集的 MAPF-LNS。[RHCR 仓库研究](https://ojs.aaai.org/index.php/AAAI/article/view/17344)、[PIBT](https://www.ijcai.org/proceedings/2019/76)、[MAPF-LNS](https://www.ijcai.org/proceedings/2021/568)。

自我检查

  1. 为什么 A → B → C 会让 B 无路可走？
  2. 为什么尝试新优先顺序时必须清空预约表？
  3. 这个程序为什么适合 3 台机器人学习，却不适合直接扩到几十台？
参考答案
  1. A 的目标在 B 的唯一通道上，而且机器人到目标后按假设停留。
  2. 各顺序是独立的试验；旧预约不属于新顺序。
  3. 程序枚举 N! 种优先顺序，排列数随机器人数量快速增长；而且它仍受固定优先级策略限制。
