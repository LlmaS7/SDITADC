当你接手、解释或继续修改本项目时，请先核对当前文件，再阅读本 README 和当前版本说明。以下记录更新于 **2026-10-13**。

1. **当前开发入口是 `project/v0.2.1_preview/`。** 当前版本采用 HTML、Three.js 3D、Canvas 2D，并拆分为使用者主窗口与独立调试窗口，源码、场景、测试、环境和输出位于版本目录。`v0.1_preview/` 保留为原 Pygame 2D 版本。新功能和修复应放在对应模块，保持模块划分。

3. **坚持已确认的范围。** 先考虑三台机器人、静态随机障碍和离散四邻域运动。主窗口显示 3D、2D 和任务列表，调试操作与内部数据放在独立窗口，两者共用一份仿真状态；3D 是简化展示，不是新的物理引擎。默认只提供普通仓库场景，紧急任务交互功能保留，不添加未请求的特殊演示预设。
4. **区分匹配最优与整体运行最优。** 当前任务分配是本轮、给定代价模型下的精确匹配，不是整个在线任务过程的全局最优。不要把估计代价、CBS 的局部优化范围或有限时域搜索夸大为全局保证。
5. **保护任务和货物状态。** 已载货机器人必须先交付；装卸动作是原子动作。取消任务只从界面列表移除，内部取消记录保留供报告及回放使用，不能直接删除记录而破坏状态机。
6. **保护学习数据和运行记录。** 不覆盖、移动或重排 `learning/maps/`。依赖安装在版本独立环境，不安装到全局 Python。`outputs/` 包含用户可能需要的场景和记录，清理前辨明用途。
7. **围绕用户已授权的工作修改。** 先确认当前实现和问题触发条件，再做针对性改动；不要擅自扩展到真实机器人、ROS、SLAM、连续控制或大型界面重构。用户的新要求优先于历史文档。
8. **如实报告验证范围。** 已运行检查、用户反馈、理论推断和未来计划分别记录。学习理解程度不能仅凭用户说“能理解”就记为已验证掌握。
9. **同步维护文档。** 修改入口、目录、状态规则、优化目标或参数后，更新本 README 与版本说明。测试按修改影响选择；文档或简单显示调整不需要无目的地重复整套长时间运行。

# SDITADC：智能仓库多机器人协作仿真

项目面向大学生智能技术应用设计类竞赛，当前已完成三机器人仓库 HTML 双窗口预览版：主窗口展示 3D、2D 和任务列表，调试窗口集中提供测试操作与内部信息。

**任务进入 → 优先级任务分配 → 多机器人路径协调 → 取货与送货 → 持续执行 → 可视化与记录。**

建模方向接近 MAPD（多机器人取送任务）与 Lifelong MAPF（持续接收目标的多机器人寻路）。当前阶段是软件仿真，算法与界面分离；真实机器人和连续运动控制不是本版本的前置条件。

## 快速启动

Windows 下双击：

```text
project/v0.2.1_preview/launch.bat
```

默认打开最大化的主窗口，不保留额外命令行窗口；点击右上角“调试窗口”可打开独立调试窗口。关闭调试窗口不影响主窗口，再次打开保持状态；关闭主窗口一并关闭调试窗口、停止后台并保存记录。启动失败时提示 `project/v0.2.1_preview/outputs/startup_error.log` 的位置。

或从 `SDITADC/` 根目录执行：

```powershell
& .\project\v0.2_preview\.venv\Scripts\python.exe .\project\v0.2_preview\main.py
```

当前机器已验证的环境是 **Python 3.14.5、pywebview 6.2.1、pythonnet 3.2.1 和 WebView2**。Three.js 0.186.1 已保存在版本内，正常运行不需要 Node、npm、Vite 或 CDN。旧 v0.1 的 pygame-ce 环境保留在旧版本内；新版本不依赖 Pygame。

Windows 独立窗口使用 WebView2 和 .NET 运行时，3D 使用 WebGL 2。不要直接双击 `frontend/index.html` 代替启动入口：页面必须连接当前仿真状态与命令服务。前端渲染库已在本地，完成环境安装后无需联网加载 3D 资源。

换电脑或环境缺失时，在版本目录重建环境：

```powershell
Set-Location .\project\v0.2_preview
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

虚拟环境依赖本机 Python 路径，不应直接复制到另一台电脑后当成可移植安装包。

### 可选运行方式

以下命令在 `project/v0.2.1_preview/` 目录中执行：

```powershell
# 独立窗口，初始暂停
.\.venv\Scripts\python.exe main.py --paused

# 启动时同时打开两个独立窗口
.\.venv\Scripts\python.exe main.py --debug-window

# 普通浏览器主页面提供调试页面入口
.\.venv\Scripts\python.exe main.py --browser

# 只启动本机服务，不自动打开窗口
.\.venv\Scripts\python.exe main.py --serve --paused

# 加载指定场景输入记录
.\.venv\Scripts\python.exe main.py --load outputs/last_scenario.json --paused
```

服务仅监听 `127.0.0.1`，默认自动选择可用端口；可通过 `--port` 指定。`--browser`、`--serve` 模式使用控制台停止服务。验证时可加 `--no-save`，避免退出时覆盖已保存记录。

### “最优”的范围

任务匹配的代价为：

```text
剩余必要动作时间
+ 到取货点的网格最短路
+ 装货时间
+ 取货点到配送点的网格最短路
+ 卸货时间
```

距离依据实际障碍地图上的 BFS。匹配使用机器人占用位掩码动态规划，针对本轮候选机器人、候选任务和给定代价精确求解。

**代价不预测未来插单及后续路径冲突带来的等待。** 分配最优不等于实际完成时间全局最优，也不等于整个持续运行过程的全局最优。

CBS 的优化目标依次是紧急任务交付时间和、全部交付时间和、停车到达时间和。其范围受固定任务归属、固定作业顺序和搜索时域限制；达到计算预算或节点上限时报告超时，不作无解或最优证明。

### 关键执行规则

- 坐标统一为 `(x, y)`，x 向右、y 向下。算法使用网格坐标，界面自行转换像素。
- 机器人最终停车后仍保留占用，不会从地图消失。作业点不作为长期停车位。
- 紧急任务的“立即调度”表示在安全边界立即重新安排；不是瞬移、碰撞穿越或中断载货交付。
- 装货开始后任务不能取消。被紧急抢占的普通任务保留编号、等级与原始创建时间。
- 普通任务长时间等待会告警，但不会自动升为紧急任务；目前不提供严格优先级下的无饥饿保证。
- 网页读取同一JSON快照，controller的单线程负责状态、命令和规划；3D与2D共用同一插值位置。刷新或打开第二个页面不另起仿真。
- 默认规划预算 2 秒、时域 260 步、CBS 节点上限 6,000；失败重试扩大时域。参数见 `config.py`。

controller.py：唯一状态拥有者和仿真时钟

## 常见界面说明

- **“取”“送”一直显示：** 它们表示当前选中任务的位置。完成后也可查看；点击另一个任务会切换，新HTML版还提供“清除高亮”。它们不代表机器人仍在装卸货。
- **取消后编号出现空缺：** 编号保留原有身份，不重新编号；取消任务从列表隐藏，记录保留在报告中。
- **自动生成关闭仍有任务：** 启动时自带 9 个普通任务；开关只控制后续自动新增。
- **全部任务完成后机器人仍移动：** 机器人可能正在前往停车位，二维预览旁的机器人状态卡会标明。
- **3D区域无法显示：** 页面会提示WebGL问题，2D和任务操作仍可使用；应检查WebView2、显卡加速及实际渲染情况，不通过修改寻路规则解决显示问题。
- **窗口弹出较慢：** 用户曾反馈旧Pygame版启动等待；旧SDL的局部测量不能代表新HTML版冷启动。新版本要加载WebView2和.NET，独立窗口页面就绪后才开始默认仿真。具体用户端启动时间尚未实测，不能把等待直接归因于CBS；测试目录不会随正常启动执行。
