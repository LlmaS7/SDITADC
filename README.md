# SDITADC：智能仓库多机器人协作仿真

项目面向大学生智能技术应用设计类竞赛，当前已完成一个三机器人二维仓库预览版：

**任务进入 → 优先级任务分配 → 多机器人路径协调 → 取货与送货 → 持续执行 → 可视化与记录。**

建模方向接近 MAPD（多机器人取送任务）与 Lifelong MAPF（持续接收目标的多机器人寻路）。当前阶段是软件仿真，算法与界面分离；真实机器人和连续运动控制不是本版本的前置条件。

## 快速启动

Windows 下双击：

```text
project/v0.1_preview/launch.bat
```

或从 `SDITADC/` 根目录执行：

```powershell
& .\project\v0.1_preview\.venv\Scripts\python.exe .\project\v0.1_preview\main.py
```

当前机器已验证的环境是 **Python 3.14.5、pygame-ce 2.5.8**。预览版唯一第三方运行依赖是 pygame-ce；学习环境中的 numpy 不构成预览版的必要依赖。

换电脑或环境缺失时，在版本目录重建环境：

```powershell
Set-Location .\project\v0.1_preview
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

虚拟环境依赖本机 Python 路径，不应直接复制到另一台电脑后当成可移植安装包。

## 当前已实现

| 部分 | 当前行为 |
|---|---|
| 地图 | 32×24 网格；20 组规则货架、20 个随机静态障碍、20 个取货作业点、4 个配送点、6 个停车位；随机种子可复现，生成时检查空闲区域连通性 |
| 机器人 | 固定三台，从相邻停车位出发；每台一次搬运一件货物，完成后继续接单或前往停车位 |
| 任务 | 前往取货、装货、送货、卸货；装卸各 2 步，多个任务可共享作业点并错峰占用 |
| 任务输入 | 默认 9 个普通任务；支持手动指定、随机新增和自动生成；自动生成默认关闭，开启后每 45 步新增一个普通任务 |
| 分配 | 按硬优先级分层，再精确最小化本轮预计完成时间总和；普通任务派出后通常保持归属 |
| 紧急任务 | 5 级为紧急；立即重新调度，选择预计最早完成的合适机器人；可抢占尚未开始装货的普通任务，原任务返回队列 |
| 载货与原子动作 | 不强行中断装卸或丢弃货物；必要时预约机器人完成当前搬运后接手紧急任务；同级紧急任务不互相抢占 |
| 多机寻路 | 带作业阶段的时空 A* 与 CBS，允许等待，检查同格冲突和对向换边；路线覆盖作业及独立停车终点 |
| 界面 | Pygame 左侧仓库、右侧任务栏；任务按编号从小到大排列，显示状态和执行机器人，支持筛选与滚动 |
| 任务操作 | 升级紧急、提升等级、取消未开始装货任务；取消后从所有界面列表移除并更新显示总数，内部记录仍保留 |
| 位置高亮 | 选中任务后标记其取送位置；“取”字位于数字标记上方，避免重叠 |
| 执行控制 | 暂停、继续、单步、速度调整、重置和重试规划；暂停时可以修改任务，位置及仿真时间保持不动 |
| 记录 | 保存地图种子、任务输入与升级等事件，记录运行指标和逐步状态；支持输入事件回放，不是中途状态恢复存档 |
| 规划异常 | 有计算预算和搜索时域；尝试扩展时域重试，仍失败或持续无进展时安全暂停并说明原因 |

### “最优”的范围

任务匹配的代价为：

```text
剩余必要动作时间
+ 到取货点的网格最短路
+ 装货时间
+ 取货点到配送点的网格最短路
+ 卸货时间
```

距离依据实际障碍地图上的 BFS。匹配使用机器人占用位掩码动态规划，针对本轮候选机器人、候选任务和给定代价精确求解。

**代价不预测未来插单及后续路径冲突带来的等待。** 分配最优不等于实际完成时间全局最优，也不等于整个持续运行过程的全局最优。

CBS 的优化目标依次是紧急任务交付时间和、全部交付时间和、停车到达时间和。其范围受固定任务归属、固定作业顺序和搜索时域限制；达到计算预算或节点上限时报告超时，不作无解或最优证明。

### 关键执行规则

- 坐标统一为 `(x, y)`，x 向右、y 向下。算法使用网格坐标，界面自行转换像素。
- 机器人最终停车后仍保留占用，不会从地图消失。作业点不作为长期停车位。
- 紧急任务的“立即调度”表示在安全边界立即重新安排；不是瞬移、碰撞穿越或中断载货交付。
- 装货开始后任务不能取消。被紧急抢占的普通任务保留编号、等级与原始创建时间。
- 普通任务长时间等待会告警，但不会自动升为紧急任务；目前不提供严格优先级下的无饥饿保证。
- Pygame 主线程读取快照并处理输入，后台单工作线程串行处理状态与规划。平滑动画只是视觉插值。
- 默认规划预算 2 秒、时域 260 步、CBS 节点上限 6,000；失败重试扩大时域。参数见 `config.py`。

## 常见界面说明

- **“取”“送”一直显示：** 它们表示当前选中任务的位置。选中任务完成后，标记仍可显示供查看历史任务；点击另一个任务会切换。它们不代表机器人仍在装卸货。
- **取消后编号出现空缺：** 编号保留原有身份，不重新编号；取消任务从列表隐藏，记录保留在报告中。
- **自动生成关闭仍有任务：** 启动时自带 9 个普通任务；开关只控制后续自动新增。
- **全部任务完成后机器人仍移动：** 机器人可能正在前往停车位，底部状态会标明。
- **窗口弹出较慢：** 用户已反馈启动等待，具体秒数和启动方式尚未确认。开发过程中测得本机原生 SDL 初始化及隐藏窗口创建等合计约 0.25 秒，地图初始化约 0.015 秒，首次规划约 0.016 秒；这些不是双击到可见窗口的完整冷启动测量，不能据此认定用户端延迟原因。CBS 在窗口创建后后台运行，`tests/` 不会随正常启动执行。
