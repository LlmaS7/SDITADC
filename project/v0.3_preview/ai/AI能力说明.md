# AI能做什么

适用版本：`v0.3_preview`。更新日期：2026-10-15。

当前AI是面向使用者的仓库业务助手，接入DeepSeek。用户用中文描述需求，模型理解意图并调用业务工具；本地程序校验参数、执行任务操作、分配机器人和协调路径。

实际能力以本文列出的十类工具为准。模型能讨论某种操作，不代表程序已经提供执行能力。

阅读入口：[本版本操作说明](../README.md) · [仓库交接说明](../../../README.md)。使用前在主窗口「AI 设置」填写Key并获取或填写模型ID；接入设置由用户操作，AI不代为修改。

## 1. 已实现的十类能力

| 能力 | 对应工具 | 能查询或执行的内容 | 示例指令 |
| --- | --- | --- | --- |
| 查询业务状态 | `get_status` | 查询任务取送地点、优先级、阶段及执行机器人；查询机器人网格位置、阶段、载货状态、当前任务、预约任务和完成数量。可指定任务ID或机器人ID | “T003现在是什么状态？”“R1正在做什么？”“哪些任务还没完成？” |
| 查询货架和作业点 | `get_locations` | 查询当前地图登记的货架、取货点和配送点；查询名称、别名及货架对应的正式取货点。可查询全部，或只查货架、取货点、配送点 | “有哪些配送点？”“四号货架对应哪个取货点？” |
| 添加取送任务 | `create_tasks` | 根据已登记地点创建一次搬运任务；支持普通、紧急及指定等级，支持批量添加 | “将四号货架的货物送到二号配送点。”“从P04送到D2，设为紧急。” |
| 提升任务优先级 | `raise_task_priorities` | 提升一级，或设为指定的更高等级；支持批量操作 | “把T003提升一级。”“把T003设为紧急。”“把T003和T004都提升到4级。” |
| 取消任务 | `cancel_tasks` | 取消尚未开始装货的任务；支持按编号或明确的关联对象取消，也支持批量取消 | “取消T003。”“取消这个任务。” |
| 查询业务指标 | `get_metrics` | 查询完成数量、待分配及已预约数量、总移动距离、路径等待、平均任务周转耗时、平均下单至装货耗时 | “已经完成多少任务？”“总共移动了多少格？”“平均任务周转耗时是多少？” |
| 指定执行 | `assign_task` | 将尚未装货任务指定给没有其他任务的机器人，或锁定其当前执行机器人；装货前可改派到空闲机器人 | “将T007分配给R3。”“T007必须由R3执行。” |
| 解除指定 | `release_task_assignment` | 装货前解除人工指定或软偏好，恢复自动分配；不会取消任务 | “解除T007的指定，恢复自动分配。”“取消这个任务的机器人偏好。” |
| 设置软偏好 | `set_task_preference` | 装货前设置优先使用的机器人；忙碌时允许其他机器人接手，可替换原人工指定 | “T007优先交给R3，忙不过来就用其他机器人。” |
| 复制任务 | `copy_task` | 从已有任务复制1～20次搬运，生成新编号；默认继承地点和等级，也可指定新等级 | “照T007再创建两次搬运。”“复制T007一份，等级设为2级。” |

查询返回的是调用时的状态。AI可以根据查询结果筛选和解释，但不能用旧对话代替实时查询。

## 2. 自然语言下单与连续对话

不要求用户输入工具名或JSON。诸如“4号”“04号”“四号”，以及“送到”“运往”等表达，由上游模型理解。

下单时，AI先查询当前地图的正式地点关系，再把需求转换成取货点ID和配送点ID。例如：

```text
用户：将四号货架的货物送到二号配送点，设为紧急。
AI：查询货架及配送点 → 找到对应取货点和配送点 → 创建5级任务。
程序：校验地点 → 创建任务 → 分配或预约机器人 → 协调路径。
AI：依据真实回执说明任务编号、取送地点及接手情况。
```

货架编号不一定等于取货点编号，AI不能自行按相同数字配对。货架或地点没有登记、名称有多个候选、缺少目的地时，应先追问。

连续回复可以补齐尚未执行的需求：

```text
用户：把四号货架的货物运走。
AI：需要送到哪个配送点？
用户：二号配送点，设为紧急。
AI：补齐地点后创建任务。
```

“这个任务”等指代使用发送消息时界面显示的关联任务。发送后再选中其他任务，不改变这条消息的关联对象；没有明确对象时应澄清。关联任务不会覆盖用户明确提出的新取送需求。

AI选项卡输入框上方显示关联任务摘要，实时更新状态、等级、取送地点、实际执行/预约/完成机器人及指定/偏好，查看这些信息无需请求模型。清除关联显示空提示，重置场景清除旧摘要；任务取消后按当前界面选择同步。摘要变化不影响草稿，也不改变已发送消息的关联对象。

标准仓库登记20组货架，中型仓库登记64组。未登记货架关系的地图仍可按正式取货点下单。自定义“包装区”“出货口”等名称需先登记到地图的 `locations`，AI不能自行给它们指定位置。

自然语言理解由模型完成；提示词要求不猜测、先澄清，但不保证任何含糊表达都能被正确理解。操作是否成功以程序回执和结果卡为准。

## 3. 任务操作的规则

### 添加任务

- 等级范围为1～5；普通任务默认2级，明确“紧急”设为5级。
- 每条任务表示一次从取货点到配送点的搬运。
- 每次批量创建工具调用最多20项；同一次需要多份相同任务时，应在同一个任务列表中明确列出。
- AI可以通过人工指定或软偏好影响任务归属，但不能直接编写或更改机器人路线。

### 提升优先级与紧急接手

- 可以提升一级，或设为指定等级；不支持降级。
- 已达到目标等级时返回“没有变化”，5级再提升仍为5级。
- 已完成或已取消的任务不能升级。
- 紧急任务由本地调度程序优先匹配。必要时可以抢占尚未装货的普通任务；不会强行中断装卸或丢弃已经载上的货物。
- 没有可立即安全接手的机器人时，可以预约完成当前搬运后接手。设为紧急不等于机器人立刻移动或任务立刻完成。

### 取消任务

- 可以取消：待分配、已预约、前往取货的任务。
- 不可以取消：已经开始装货、正在配送、正在卸货、已完成或已取消的任务。
- 取消后从任务列表隐藏，内部记录保留，其他任务编号不重排。
- 每次批量提升或取消工具调用同样最多20项。

### 指定执行、解除指定与软偏好

- 仅待分配、已预约、前往取货阶段允许调整分配方式；装货开始后，三种操作均拒绝。
- 指定的目标机器人不能执行其他任务或预约其他任务。可以锁定任务的当前执行机器人，也可以在装货前改派到空闲或正在回停车位的机器人；不强行抢走忙碌机器人的其他订单。
- 每台机器人同时最多接受一个未结束的人工指定任务。本版没有人工任务队列，不能以连续指定来预约该机器人的多个后续订单。
- 人工指定是约束，任务只交给指定机器人；其他事件或重规划不会自行解除。紧急任务可暂时抢占尚未装货的普通指定任务，后者保留指定关系等待同一机器人。指定本身不改变任务等级，若绕过待分配任务的硬优先级则拒绝。
- 解除指定将分配方式恢复为自动，并重新计算归属和路线；不是取消任务，也不保证仍由原机器人执行。
- 软偏好与人工指定不同：先满足各等级的分配数量，再尽量满足可立即接手机器人的偏好，最后最小化预计完成时间。偏好可能增加行驶距离；忙碌机器人不因普通任务偏好而被强行抢占。
- 查询、结果卡和任务列表区分“人工指定/软偏好机器人”与“实际执行机器人”。软偏好不保证实际执行者，已指定也不等于已经开始移动。
- 已经采用相同分配方式和同一目标机器人时，返回“无需改变”；恢复自动分配时同时解除人工指定或软偏好。

调度先匹配紧急接手，再匹配剩余空闲机器人。各阶段在可选槽位及人工约束下优化优先级、偏好和预计完成时间，不保证整个在线过程全局最优。

### 复制任务

- 原任务可以处于任意阶段，包括已完成或已取消；复制只是明确创建新任务，不恢复或修改旧任务。
- 默认复制原取货点、配送点和等级；原任务是5级时，新任务也默认5级。用户明确要求不同等级时可以覆盖。
- 每次最多复制20份，默认1份。每份都有独立新编号和创建时刻，不继承原状态、完成时间、执行机器人、人工指定或软偏好。
- 回执标注“复制自Txxx”；重试去重、部分成功和规划失败规则与创建任务相同。
- 分配方式和复制来源随本地报告及输入事件保存，加载回放不再请求AI。

### 四个新工具的调用参数

下表供维护者核对工具接口；使用者直接输入中文指令即可。任务和机器人ID使用查询返回的字符串，不把“货架编号”当任务编号。

| 工具 | 参数示例 | 默认值及限制 |
| --- | --- | --- |
| `assign_task` | `{"task_id":"T007","robot_id":"R3"}` | 两项必填；校验装货阶段、目标机器人是否忙碌、已有指定关系及硬优先级 |
| `release_task_assignment` | `{"task_id":"T007"}` | 必填任务ID；恢复自动分配，不删除任务 |
| `set_task_preference` | `{"task_id":"T007","robot_id":"R3"}` | 两项必填；目标可以忙碌，设置的是偏好而非人工预约；可替换原人工指定 |
| `copy_task` | `{"task_id":"T007","count":2,"priority":2}` | `task_id`为来源任务；`count`默认1，范围1～20；省略`priority`继承原等级，填写时为1～5 |

单次指定、解除或偏好工具调用只处理一个任务；多个任务由模型分别调用。创建、提升、取消和复制的数量上限以各次工具调用为单位，不是一个聊天请求的统一事务上限。

查询及回执包含以下字段，供模型区分请求与实际结果：

| 字段 | 含义 |
| --- | --- |
| `assignment_mode` | `auto`自动、`forced`人工指定、`preferred`软偏好 |
| `requested_robot` | 指定或偏好的机器人；自动模式为`null` |
| `assigned_robot` | 当前或历史实际接手机器人；待分配时可能为`null` |
| `copied_from` | 新任务的复制来源ID；普通创建为`null` |

### 常见拒绝与正确解释

| 情况 | 程序行为 |
| --- | --- |
| 目标机器人忙于其他任务或已有其他人工指定任务 | 拒绝指定；不取消其他任务，不自动改成预约 |
| 任务已开始装货、正在配送/卸货或已经结束 | 拒绝调整分配方式；已完成或取消的任务仍可作为复制来源 |
| 指定会绕过待分配任务的硬优先级 | 拒绝；人工指定不会自行提升等级 |
| 任务或机器人不存在、复制数量不合法 | 校验失败，不执行该次操作 |
| 操作已经生效，但规划预算内没有可执行路线 | 保留已生效操作并说明路线暂不可用，不能宣称机器人已出发 |

## 4. 暂不支持的操作

以下内容没有开放给AI执行：

- 暂停、继续、单步、调整仿真速度、重置场景。
- 切换地图、修改障碍、地图种子或机器人数量。
- 打开调试窗口、添加随机任务、开关自动生成。
- 保存或加载运行记录，修改API Key、接入地址或模型设置。
- 强行抢走忙碌机器人的其他任务、人工预约忙碌机器人、遥控移动、手写路线、强制避让或抢占载货任务。
- 修改已创建任务的取货点或配送点；需要调整时只能在满足取消条件后明确取消并重新创建。
- 降低任务优先级、撤销已生效操作、恢复已取消任务。
- 查询真实库存、货物品种或重量；“全部库存”没有可直接执行的数量含义，需先明确搬运次数。
- 任意位置或货架之间的搬运、故障处置、动态封路、充电管理、真实机器人控制。
- 定时下单、周期任务、主动监控业务并自行创建或修改任务。
- 提供精确完成时刻、实际耗时秒数，或保证在线全局最优与任意布局无死锁。

这些调试或扩展能力不因用户在聊天中提出要求而自动获得授权或实现。

## 5. 使用时需要区分的状态与结果

**已创建、已分配、已预约、装货、配送、卸货、已完成是不同阶段。** 阶段本身不能证明机器人当前正在移动。仿真暂停时也可以通过AI创建任务、更新分配和规划，正常操作会保持暂停；AI不接收暂停、仿真时刻、地图种子等调试字段，因此不能替用户恢复运行。

批量操作先整批预检，再逐项执行。中途失败或路线暂不可用时，已经成功的操作保留，剩余操作可能停止，不保证整体回滚。任务创建成功与路线暂时不可用可以同时发生；网络报错或超时也不能证明任务没有创建，不应直接重复下单。

“停止回复”阻止后续生成和尚未开始的工具调用，已经开始的原子动作可能完成，已经生效的操作不会撤销。当前一次处理一条消息，等待期间可以编辑下一条草稿。

指标耗时使用**调度时间步**，不是秒。平均下单至装货耗时包含去取货的路程，不能解释为纯排队等待。

聊天只在本次运行保留。长对话会尝试摘要，失败时裁剪旧上下文；历史状态仍需重新查询。更换场景、API地址或模型等上下文变化会隔离旧会话，防止旧请求操作新场景的同名任务。

API Key默认仅本次运行有效。选择“记住密钥”才存入Windows凭据管理器；保存、获取模型或重新打开设置后显示固定圆点，圆点只表示同地址已配置密钥，不代表真实长度或认证通过。更换地址需明确输入新Key，删除密钥后圆点消失。模型列表请求成功与聊天/工具往返成功是不同验证阶段。

## 6. 对应代码

| 文件 | 职责 |
| --- | --- |
| `tools.py` | 十类工具定义、参数校验和对AI可见的业务数据 |
| `prompts.py` | 自然语言理解要求、澄清规则和业务边界 |
| `executor.py` | 在Controller线程执行操作、预检、去重和真实结果回执 |
| `service.py` | 模型请求、工具往返、停止和场景隔离 |
| `provider.py` | DeepSeek模型查询及流式接口 |
| `configuration.py` / `credentials.py` | 接入配置与Windows凭据存储 |
| `conversation.py` | 本次运行的对话上下文和摘要 |

这些模块配合现有调度与路径规划核心工作：AI决定调用哪类业务工具及其参数，本地程序校验指定或偏好，在约束下决定归属及怎样行驶。
