# 统一地图规格（sditadc-map v1）

地图独立于寻路算法和 2D/3D 渲染，文件放在本目录，命名为 `英文字母_数字或短横线.json`。调试窗口点击“刷新列表”，选择地图，然后“应用并重置”。切换会清空当前任务、重置机器人和时刻，并保持暂停；需要保留运行记录时先保存。

当前提供：

- `warehouse.json`：原 32×24 标准仓库，固定布局和作业点，按种子叠加最多 20 个静态随机障碍，机器人上限 6 台。
- `warehouse_64x48.json`：64×48 中型仓库，8 排×8 列共 64 组 5×3 货架；横纵间隙至少 2 格，中央横纵主通道各 4 格。64 个取货点、4 个配送点、11 个停车位，最多 8 个相邻起点位于左上方，机器人上限 8 台。固定布局，通道保持畅通。
- `movingai_warehouse.json`：本地 `warehouse-10-20-10-2-1.map` 转换的 161×63 仓库；SDITADC 单独配置了取送点和相邻起点，未使用官方 `.scen` 作为取送任务。没有叠加随机障碍，机器人上限 6 台；该地图货架间存在单格通道，容量按通道条件设置。

## 文件结构

下面是一张可直接使用的最小地图。坐标原点为左上角，x 向右、y 向下，从 0 开始。地图只采用四方向移动，机器人占一格；每一行字符串对应一行网格。

```json
{
  "format": "sditadc-map",
  "version": 1,
  "name": "小仓库",
  "grid": {
    "width": 9,
    "height": 7,
    "rows": [
      "#########",
      "#.......#",
      "#.......#",
      "#..RR...#",
      "#.......#",
      "#.......#",
      "#########"
    ]
  },
  "points": {
    "starts": [[1, 1], [2, 1], [3, 1]],
    "parking": [[1, 1], [2, 1], [3, 1], [7, 1], [1, 5], [7, 5]],
    "pickups": [[3, 2], [4, 2]],
    "deliveries": [[4, 5]]
  },
  "random_obstacles": {"count": 0},
  "robots": {"default_count": 3, "max_count": 3}
}
```

| 字符 | 含义 | 通行 | 3D 展示 |
|---|---|---|---|
| `.` | 地面 | 可以 | 地板 |
| `#` | 墙体 | 不可以 | 矮墙 |
| `R` | 货架 | 不可以 | 货架 |
| `O` | 固定杂物 | 不可以 | 箱形障碍 |

边界不强制设墙；越出地图始终不可通行。货架可以是不规则形状，3D 不会将空洞填成实心。作业点单独配置在可通行地面上；不要把取货点设在货架内部。

`points` 中的列表顺序就是界面编号：取货点 1、2…，配送点 D1、D2…，起点池中的前 N 个坐标依次对应 R1～RN。停车位数量必须不少于机器人上限，且不能与取送点重叠。取货和配送点也不能互相重叠。

`robots.default_count` 是启动默认数量，`robots.max_count` 是本地图上限；必须满足 `1 ≤ default_count ≤ max_count ≤ 12`，且上限不超过起点池和停车位数量。`starts` 是候选起点池，互不重复、全部属于停车位，并按相邻顺序排列，确保前 N 个起点四方向连通。缺少 `robots` 的旧地图按起点池容量推导上限（最多12），默认最多3台；原来的三起点地图继续只有3台容量。每类点最多 64 个。地图宽高各为 3～256，文件不超过 2 MB；所有地面格须四方向连通。这些是当前预览版的支持范围，不是 MAPF 的通用约束。通过地图检查只证明几何及业务坐标可用，狭窄通道仍可能触发规划预算限制；无法规划时会暂停。

`random_obstacles` 可省略（默认不添加）。`count` 为期望新增数量，最多 200；可选 `region: [left, top, right, bottom]` 限定区域，右和下边界不包含，默认覆盖整张地图。生成时保护作业点、停车位和邻格并检查连通性；空间不足时实际数量可能小于期望值。`O` 表示的已有障碍不计入新增数量。

相同文件、数量和种子生成相同布局与初始任务。没有随机障碍的地图更换种子不会改变网格，但仍会改变随机任务。保存记录会嵌入已生成的完整地图快照，回放不再依赖原地图文件是否存在或已被修改。保存记录同时包含机器人数量；旧记录没有数量时按3台读取，没有地图快照时使用标准仓库和种子。限时搜索可能在不同运行中选用CBS或预约寻路，因此输入回放保证恢复地图、数量和输入事件，不承诺不同机器上每一步的路线完全一致。

## 业务名称与货架取货关系（0.3可选扩展）

顶层可选 `locations` 保存地图自身的业务事实，兼容原sditadc-map v1。旧地图不填时只有默认编号作业点，不会自动生成货架归属。

示例片段（坐标需按真实地图填写，本例是独立字段格式示意）：

```json
{
  "locations": {
    "pickups": [{"id": "P02", "name": "补货取货点", "aliases": ["补货口"]}],
    "deliveries": [{"id": "D1", "name": "包装区", "aliases": ["包装工位"]}],
    "shelves": [
      {"id": "S04", "name": "4号货架", "aliases": ["补货架"], "pickup_id": "P02", "cells": [[5, 4], [6, 4], [7, 4], [5, 5]]}
    ]
  }
}
```

- pickup和delivery的ID引用 `points` 一基顺序，规范为P01/P02及D1/D2；不能用名称重排坐标或改变任务身份。
- 名称/别名为1至80字符，最多12个别名；列表可只覆盖需要命名的点。
- 货架ID以S开头，与机器人R编号区分；货架编号可以与取货点编号不同。
- `cells`必须是实际R货架格、四方向连通、不重复、不与其他登记货架重叠。`pickup_id`必须存在且其作业点邻接这组货架。
- 同一别名可以对应多个地点：目录保留全部候选，由LLM结合语境判断，无法明确时追问；本地不编写中文数字或措辞解析器。
- LLM得到名称、别名、取货点关系及作业位置，不取得完整货架格或调试状态。工具执行依旧使用P/D规范ID。
- 标准仓库已登记20组，中型仓库64组；MovingAI取货点邻接多组货架，保留未登记状态，不能假定其取货点编号就是货架编号。
- 保存的地图快照包含这些名称和映射；加载旧快照时维持其原数据，不用当前地图文件替换历史归属。

编辑后用 `map_tools.py validate` 检查，在已有场景入口应用，或启动时载入该地图。AI没有编辑地图的工具。

## 数量设置

调试窗口“场景设置”中选择机器人数量，选项随地图上限更新。切换到容量更小的地图时，尚未应用的数量会显示为新上限；点击“应用并重置”后才改变仿真。后端也会拒绝越界数量，不会截断或重叠生成机器人。

现有地图默认3台：标准仓库最大6台，中型仓库最大8台，MovingAI仓库最大6台。程序目前最多支持12台，作为精确任务匹配和限时多机规划的规模边界；地图空间足够不等于任意数量都能快速规划。

要提高某张地图上限，先扩展有效的 `points.starts` 和 `points.parking`，再修改 `robots.max_count`，运行地图校验。示例中的小地图只有三个起点，上限因此为3。

## 新增地图

1. 复制现有 JSON，修改尺寸、网格行和作业坐标，文件名使用不同名称。
2. 在版本目录执行校验：

   ```powershell
   .\.venv\Scripts\python.exe map_tools.py validate maps/my_warehouse.json
   ```

3. 调试窗口刷新列表，选择新地图和机器人数量，应用并重置。无效地图会显示错误且不能选择；若文件在选择后变更，应用时再次检查，失败保留原场景。

也可启动时指定文件名（省略 `.json`）：

```powershell
.\.venv\Scripts\python.exe main.py --map my_warehouse --robots 3 --paused
```

## 导入 MovingAI

`.map` 提供地面和障碍，不含仓库业务点；`.scen` 提供静态起终点，不等同于取送任务。先创建一个 `points.json`，内容就是上面 `points` 对象的四组坐标，再执行：

```powershell
.\.venv\Scripts\python.exe map_tools.py import-movingai path/to/map.map --points path/to/points.json --name "我的仓库" --blocked-kind shelves --output maps/my_warehouse.json
```

转换器支持 `type octile` 文件头及 `. G @ O T` 字符，但导入后仍采用四方向移动。`.`、`G` 转为地面；不可通行格默认转为墙，指定 `--blocked-kind shelves` 时内部阻塞格转为货架、边界阻塞格仍转为墙。特殊地形 `S/W` 会报错，需先明确业务语义。转换不会覆盖已有输出文件。

内置 MovingAI 仓库的来源为 [MovingAI MAPF Benchmark](https://www.movingai.com/benchmarks/mapf/index.html)，原文件位于 `learning/maps/movingai/warehouse-10-20-10-2-1/`。数据采用 [Open Data Commons Attribution License 1.0](https://opendatacommons.org/licenses/by/1-0/)，请保留来源归属。取送点等配置由 SDITADC 添加，不代表官方场景。

## 维护入口

- `map_format.py`：格式版本、语法和连通性校验、地图目录发现。
- `warehouse.py`：实例化地图及随机障碍、距离计算、快照导出。
- `map_tools.py`：命令行校验和 MovingAI 转换。
- `schema/map.schema.json`：编辑器用 JSON Schema；跨点关系和连通性由 Python 校验器检查。

后续编辑器、不同地图来源、2D/3D 渲染共用这一规格。地图规格与程序版本分别编号，不需要因每次界面升级而改变地图文件。
