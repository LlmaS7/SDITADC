把 A* 扩展到双机器人协同

这一课把上一课的冲突概念落到程序里：先让两台机器人各自找最短路，再让 A* 把“时间”和“等待”也纳入搜索。

本课结束时，你应该能解释

  • 为什么多机搜索状态要从“格子”变成“格子 + 时间”。
  • 等待为什么是一种合法动作，而不是程序卡住。
  • 优先规划怎样用先规划机器人的路径约束后规划机器人。
  • 这种简单方法能解决什么，又会在哪些地图上失败。

一句话：单机 A* 搜索“我在哪”；协同 A* 搜索“我在什么时间位于哪里”。

1. 两条最短路，为什么会撞？

A 的起点是 (1, 2)，目标是 (3, 2)；B 从 (2, 1) 去 (2, 3)。坐标写成 (x, y)，x 向右增加，y 向下增加。

两条独立最短路都是两步，但它们在第 1 步同时到达中央格 (2, 2)。路径长度都正确，组合起来却不安全。

优先规划：先 A，再 B

时间A 的位置B 的位置
0(1, 2)(2, 1)
1(2, 2)(2, 1)
2(3, 2)(2, 2)
3(3, 2)(2, 3)

观察：B 在时间 0 到 1 留在原地。A 先通过中央格，B 再通过，所以不会同一时刻占用同一格。

2. 从单机 A* 到带时间的 A*

单机 A* 的一个搜索节点可以写成 (x, y)。例如 (2, 2) 只表示机器人到了中央格。

多机时，同一个格子在不同时间可能安全，也可能冲突，因此节点改为：

状态 = (x, y, t)
  • (2, 2, 1)：机器人在第 1 个时间步位于中央格。
  • (2, 2, 2)：它在第 2 个时间步位于中央格。位置一样，时间不同，是另一个搜索状态。

每次移动或等待都消耗一个时间步。A* 的优先级仍然是 已走时间 + 到目标的估计时间，这里的估计继续使用曼哈顿距离：

f = t + |x - goal_x| + |y - goal_y|

等待不改变位置，但时间增加：(x, y, t) → (x, y, t + 1)。它让机器人能等走廊或路口空出来。

3. 优先规划怎样安排两台机器人

  1. 按固定顺序规划机器人，这里先规划 A。
  2. 把 A 每个时间点所在的格子记成“已占用”。
  3. 规划 B 时，不允许它在同一时间进入 A 已占用的格子。
  4. 同时记录 A 每一步经过的边，避免 B 与 A 反向交换位置。
  5. 如果 B 当前走不了，就让带时间的 A* 尝试等待，直到找到安全路线。

上一课提到的两种冲突，对应两类预约：

  • 格子预约：(时间, 位置)，检查顶点冲突。
  • 边预约：(时间, 起点, 终点)，检查两台机器人是否反向交换位置。

本例中，A 的路径预约了 (1, (2, 2))。B 如果第 1 步进入中央格，就会被拒绝；等待一步后，B 在第 2 步到达中央格，此时 A 已经离开。

重点看下面几处，不需要一次读懂每个标点：

  • ACTIONS 多了 (0, 0)，它就是等待动作。
  • State = (x, y, time) 表示搜索节点包含时间。
  • reserved_vertices 存储某一时刻不能进入的格子。
  • reserved_edges 存储已规划机器人的移动方向，用于拒绝反向交换。

5. 这套方法的边界

优先规划简单，适合先做出可解释的小型多机器人程序。它把先规划机器人的路线固定下来，再让后面的机器人绕开。

固定的先后顺序可能让某台机器人无路可走，即使换一个规划顺序就能成功。因此，“找不到路”不总是说明地图上没有任何多机解；也可能只是这次优先级选择不合适。更先进的方法会重新安排优先级，或同时搜索多台机器人的联合状态。

当前程序为了让概念清楚，还使用了固定目标、四方向移动、每步耗时相同、目标处停留、有限搜索时间。之后接入仓库地图前，再逐步放宽这些假设。

6. 学习检查

  1. 为什么 (2, 2, 1) 和 (2, 2, 2) 要视为两个状态？
  2. 程序里的等待动作改变了什么，没有改变什么？
  3. 如果交换 ROBOTS 中 A、B 的顺序，谁先预约路径？
  4. 优先规划返回“没有路径”，能否证明不存在安全方案？为什么？
展开参考答案
  1. 虽然位置相同，但其他机器人在这两个时间点的占用情况可能不同。
  2. 时间增加 1，位置不变。
  3. 字典中排在前面的机器人先规划并留下预约。
  4. 不能。当前顺序可能造成死路，改顺序或联合规划可能找到方案。
